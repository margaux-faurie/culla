# Distribution: per-user NSIS + signed updater; Windows code signing deferred

## Context and problem statement

Culla ships to Windows users from GitHub. The author is an individual in France. Installs should not need admin rights, and users should get updates. How is Culla packaged, updated and signed?

## Considered options

* Installer: NSIS per-user, MSI (WiX), MSIX / Microsoft Store
* Updates: `tauri-plugin-updater`, manual downloads only
* Signing: Azure Artifact Signing, OV certificate, EV certificate, SignPath Foundation, unsigned for now

## Decision outcome

Chosen option: "Per-user NSIS, `tauri-plugin-updater`, unsigned v1, then SignPath Foundation", because it is free, needs no admin rights, and is the only signing route open to an individual in the EU.

* `tauri-apps/tauri-action@v1` on `windows-latest` builds the NSIS installer as a draft GitHub Release ([pipelines](https://v2.tauri.app/distribute/pipelines/github/)). NSIS installs into `%LOCALAPPDATA%` without admin. MSI needs WiX and adds little.
* [`tauri-plugin-updater`](https://v2.tauri.app/plugin/updater/) has its own mandatory signing key, separate from Authenticode, so it works on unsigned builds. `latest.json` is generated by tauri-action and served over HTTPS.
* Azure Artifact Signing is open to individuals only in the US and Canada ([quickstart](https://learn.microsoft.com/azure/artifact-signing/quickstart)). OV costs $150–300/year with an HSM or token. EV no longer gives instant SmartScreen reputation ([ToDesktop](https://www.todesktop.com/blog/posts/windows-apps-psa-ev-certs-do-not-grant-immediate-reputation-anymore)).
* [SignPath Foundation](https://signpath.org/terms) is free for OSI-licensed projects but needs an already released project, MFA and a code signing policy.
* winget manifest after v1. Microsoft Store (MSIX via winapp CLI) is a v2 option.

### Consequences

* Good, because releases cost nothing and updates work from day one.
* Bad, because v1 users see a SmartScreen warning; the README explains it.
* Bad, because losing the updater private key strands every installed user; custody is in [releasing.md](../releasing.md).
